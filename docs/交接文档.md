## 一、项目一句话说明

给 Anbernic RG35XX Pro 掌机做一个**图形化**的文件传输工具，替代 SSH / Samba / WinSCP，让不懂命令行的用户能把 PC 上的游戏、存档传到掌机。

**核心差异点**：掌机端是服务端，**任何写操作都必须经掌机侧物理确认**，PC 端无权绕过。这是现有方案（SSH/Samba/WinSCP）都不具备的能力。

### 应用发布方式（社区已验证，务必照抄）

参考社区项目 Grout（rommapp 官方 RomM 客户端）的做法，**这是唯一在 H700 原厂固件上
跑通的生产级第三方应用**，其 `scripts/Anbernic/Grout.sh` 注释原文说明了目录规则：

> "The stock launcher lists every *.sh in Roms/APPS and runs it with $0 set to its path,
> so the payload lives in the sibling folder (**directories are not listed as apps**)."

```
Roms/
├── APPS/
│   ├── PocketTransfer.sh        # 启动脚本，必须直接放 APPS 根目录
│   ├── PocketTransfer/          # 负载目录（启动脚本的兄弟目录）
│   │   ├── PocketTransfer       # aarch64 可执行文件
│   │   ├── lib/                 # 依赖库（SDL2）
│   │   ├── assets/              # 图标、字体
│   │   └── logs/                # 运行时日志（脚本自动创建）
│   └── Imgs/
│       └── PocketTransfer.png   # 菜单图标（是 APPS/Imgs/，不是 Roms/Imgs/）
```

用户从「Apps Center → APPS」点开。**进程不退出就回不了菜单**，所以必须提供退出机制。

⚠️ **不要写成 `Roms/APPS/PocketTransfer/{二进制, launcher.sh}` —— 目录不会出现在菜单里。**

### 为什么掌机端用 Python 而不是 C（v1.3 决策）

固件自带完整 Python 桌面栈（Python 3.10.12 / Pillow 9.0.1 / pysdl2 0.9.17；SDL2 双版本，pysdl2 用 **2.28.5**），
**原厂 5 个应用全部是 Python 写的**（时钟 / 图片浏览器 / 魔改系统工具 / 魔改系统设置 / 瑞士小刀抓取器），
源码就在 `/mnt/mmc/Roms/APPS/<name>/`，结构是 `main.py` + `graphic.py` + `input.py` + `app.py`。

**含义**：我们要做的事，原厂已经用 Python 做过一遍。跟着走，风险最低。

C 版方案（静态 aarch64 二进制）保留作性能兜底与参考实现，不作为主线。

### 为什么不用 SSH 做产品功能（重要，勿推翻）

原厂固件自带 SSH 和 Samba，但**复用它们会导致需求 ①（自动发现）无法实现**，且存在**架构级障碍**：

> SSH 是单方面主从控制，PC 一连上即拥有 root 权限。而本项目要求"掌机掌握最终决定权"，
> 任何复用 SSH 的方案在架构上都**不可能**实现掌机侧确认。

这不是实现难度问题，是架构约束。

**但开发调试要用 SSH** —— 阶段 0 抓真机信息全靠它。用完关掉。

### ⚠️ 显示层：唯一可行路径（2026-10-05 实机确认）

**必须用 SDL2 的 `SDL_WINDOW_FULLSCREEN_DESKTOP`。**

本机显示子系统是 **Allwinner DispEngine 多图层合成器**（`/dev/disp`），
`/dev/fb0` 只是**最底层图层**。原厂菜单 `dmenu.bin` 退出时不清图层，
残留的"加载中"画面会**完全盖住**你写在 fb0 上的内容。

铁证：把 fb0 整块 7MB 扫一遍，找不到 dmenu 画的画面。
`dmenu.bin` 是静态链接，字符串含 `/dev/disp`、`/dev/ion`、`CdcIonAlloc`、`DisplayEngine Frequency`。

**→ 详见 [`RG35XXPro-开发成功经验.md`](RG35XXPro-开发成功经验.md) 第二章。**

> 原 `技术栈决策v1.3.md` 曾写「EGL 不通、SDL2 会失败、唯一路径是裸 fb0」——
> **该结论已作废**，原因与证据见该文档文末附录。

## 六、核心机制设计（实现时必须遵守）

### 6.1 角色划分

**掌机端 = 服务端（持有文件与最终决定权）**
**PC 端 = 客户端（主动连接，所有写操作等待掌机确认）**

这是"掌机侧确认"能成立的架构根基。**不要把角色反过来。**

### 6.2 锁定状态机

```
启动 → 锁定（只读）
         │ START 键
         ▼
      解锁（可弹窗确认）
         │
         ├─ 收到写请求 → 确认弹窗 → A 执行 / B 拒绝
         │                            └─ 30 秒无响应 → 自动拒绝
         └─ 注意：解锁 ≠ 放行一切，每个写操作仍需逐次确认
```

**安全默认值**：
- 每次启动默认锁定（解锁状态**不跨程序运行持久化**）
- 超时视为拒绝
- 震动马达轻震 200ms 提示弹窗出现
- 弹窗期间忽略重复请求（防连击）
- PC 端等待期间必须禁用所有写操作按钮

### 6.3 路径三区分类（v1.2 修订 —— 取代"Roms/ 白名单"）

```
安全区（一次确认）
  Roms/   saves_RA/   states_RA/   save/   bios/   Imgs/

警告区（两次确认：目录警告 + 标准确认）
  System/   config/   TF 卡根下的 *.sh / *.ini / *.cfg

禁止区（直接拒绝，不弹窗）
  /mnt/vendor   /etc  /usr  /sys  /proc  /dev  /boot
  任何超出 BASE_PATH 的路径
```

**为什么改**：原厂 RetroArch 被打补丁，**存档路径被重定向**——
`Roms/GBA/Game.gba` 的存档实际在 `saves_RA/Roms/GBA/Game.srm`，状态档在 `states_RA/`，
独立模拟器（PPSSPP/Drastic/OpenBOR）存档在 `save/`。
若按 v1.1 的「不在 `Roms/` 下就二次确认」，用户传存档会一路撞上红字警告，
而那其实是完全安全的操作 —— 真正的危险反而被警告稀释。

### 6.4 存档落点映射（v1.2 新增，PC 端实现时用得上）

| 用户要传的 | ROM 所在 | 应传到 |
|---|---|---|
| RetroArch 存档 `.srm/.sav` | `Roms/GBA/Game.gba` | `saves_RA/Roms/GBA/Game.srm` |
| RetroArch 状态档 | `Roms/GBA/Game.gba` | `states_RA/Roms/GBA/Game.state` |
| PPSSPP/Drastic 存档 | `Roms/PSP/Game.iso` | `save/` 对应子目录 |
| BIOS | —— | `bios/` |
| 普通 ROM | —— | `Roms/<平台>/` |

BIOS 另注：RetroArch 的 system 目录在只读 appfs `/mnt/vendor/deep/retro/system`。

### 6.5 退出机制

| 当前状态 | 退出行为 |
|---|---|
| **空闲**（主界面走马灯） | 直接退出，返回 Apps Center |
| **待确认**（显示弹窗） | 退出即视为拒绝该请求，**不再多问一遍** |
| **传输中**（进度条） | 先弹警告「传输会中断」，A 确认 / B 取消 |

退出后收尾：关套接字 → 清理 `.part` → 状态复位 → 释放 SDL2。

### 6.6 卡根与卡槽（v1.2 重写）

**不靠程序探测挂载点，靠启动脚本自算并 export：**

```bash
progdir="$(cd "$(dirname "$0")"; pwd)"
basedir="$(cd "$progdir/../.."; pwd)"    # Roms/APPS -> 卡根
export BASE_PATH="$basedir"
```

- 装在 TF1 → `BASE_PATH=/mnt/mmc`，程序管 TF1
- 装在 TF2 → `BASE_PATH=/mnt/sdcard`，程序管 TF2
- **双卡用户把发布包拷两份到两张卡**，各管各的
- 挂载探测**降级为纯展示用途**，只回答"另一张卡在不在"
- 找不到 `Roms/` 则自动创建

## 七、通信协议

### 7.1 报文格式

```
┌─────────────┬─────────────┬─────────────┬─────────────┐
│ MAGIC (2B)  │ TYPE  (2B)  │ LENGTH (4B) │  PAYLOAD    │
│   0x504B    │  操作码     │  负载字节数  │  变长数据    │
└─────────────┴─────────────┴─────────────┘
```

- MAGIC = `0x504B`（"PK"），用于丢弃非法包和 TCP 流错位恢复
- TYPE = 操作码（见下表）
- LENGTH = **网络字节序（大端）**
- PAYLOAD = JSON（文本操作）或二进制块（文件传输）

**注意**：所有整数用固定宽度类型，禁止依赖 C 的 `int`/`long` 宽度。

### 7.2 操作码

| 类别 | TYPE | 名称 | 方向 |
|---|---|---|---|
| 系统 | 0x0001 | `PING` | PC→掌机 |
| 系统 | 0x0002 | `PONG` | 掌机→PC |
| 系统 | 0x0003 | `GET_DEVICE_INFO` | PC→掌机 |
| 系统 | 0x0004 | `DEVICE_INFO` | 掌机→PC |
| 发现 | 0x0010 | `BEACON` | 掌机→广播 |
| 文件 | 0x0020 | `LIST_DIR` | PC→掌机 |
| 文件 | 0x0021 | `DIR_LISTING` | 掌机→PC |
| 文件 | 0x0022 | `DELETE` | PC→掌机（**需确认**） |
| 文件 | 0x0023 | `DELETED` | 掌机→PC |
| 文件 | 0x0024 | `RENAME` | PC→掌机（**需确认**） |
| 文件 | 0x0025 | `RENAMED` | 掌机→PC |
| 文件 | 0x0026 | `MKDIR` | PC→掌机（**需确认**） |
| 文件 | 0x0027 | `MKDIR_OK` | 掌机→PC |
| 传输 | 0x0030 | `UPLOAD_START` | PC→掌机（**需确认**） |
| 传输 | 0x0031 | `UPLOAD_DATA` | PC→掌机（64KB 块） |
| 传输 | 0x0032 | `UPLOAD_END` | PC→掌机 |
| 传输 | 0x0033 | `UPLOAD_ACK` | 掌机→PC（含已接收偏移，断点续传用） |
| 传输 | 0x0034 | `UPLOAD_RESULT` | 掌机→PC |
| **下载** | **0x0035** | **`DOWNLOAD_START`** | **PC→掌机**（`from_offset`） |
| **下载** | **0x0036** | **`DOWNLOAD_DATA`** | **掌机→PC**（64KB 块） |
| **下载** | **0x0037** | **`DOWNLOAD_END`** | **掌机→PC** |
| **下载** | **0x0038** | **`DOWNLOAD_RESULT`** | **掌机→PC**（含总大小） |
| 确认 | 0x0040 | `CONFIRM_REQUIRED` | 掌机→PC |
| 确认 | 0x0041 | `CONFIRM_RESULT` | 掌机→PC |
| 错误 | 0x00F0 | `ERROR` | 双向 |

### 7.3 设备信息报文

```json
{
  "device_name": "RG35XX Pro",
  "device_id": "a3f2c8e1",
  "ip": "192.168.1.105",
  "port": 48200,
  "version": 1,
  "locked": false,
  "base_path": "/mnt/mmc",
  "storage": [
    { "slot": "TF1", "path": "/mnt/mmc",    "free_mb": 18432, "is_current": true  },
    { "slot": "TF2", "path": "/mnt/sdcard", "free_mb": 102400, "is_current": false }
  ]
}
```

`base_path` 来自 `BASE_PATH` 环境变量；`storage` 是**数组**，长度取决于实际探测到的卡槽数。

### 7.4 确认流程时序（以删除为例）

```
PC 掌机                        掌机端
 │─── DELETE {path} ───────────►│
 │                              │─ 校验路径三区分类
 │                              │─ 震动马达轻震 200ms
 │                              │─ 显示确认弹窗
 │                              │─ 25 秒后显示倒计时
 │◄── CONFIRM_REQUIRED ─────────│
 │                              │
 │   （PC 显示"等待掌机确认"）    │  ← 用户按 A 或 B
 │                              │
 │◄── CONFIRM_RESULT{approved} ──│
 │                              │─ 执行 / 拒绝
 │◄── DELETED{ok} ─────────────│
```

### 7.5 自动发现

掌机每 5 秒向 `255.255.255.255:48211` 发送 `BEACON`。

**PC 端必须保留「手动输入 IP」兜底入口** —— 部分企业级 AP 会屏蔽 UDP 广播，这不是可选项。

### 8.6 launcher.sh 完整内容（**已实机验证版本**）

```bash
#!/bin/bash
# PocketTransfer launcher for the Anbernic stock OS.
# The stock launcher lists every *.sh in Roms/APPS and runs it with $0 set to its path,
# so the payload lives in the sibling "PocketTransfer" folder.
# 本脚本系「实际部署并验证通过」的版本（v1.4）。

set -u
progdir="$(cd "$(dirname "$0")" && pwd)"
basedir="$(cd "$progdir/../.." && pwd)"    # Roms/APPS -> 卡根
APPDIR="$progdir/PocketTransfer"

export BASE_PATH="$basedir"                 # 卡根（程序据此认定管哪张卡）
export PYSDL2_DLL_PATH="/usr/lib"           # ★ 必须！原厂 5 个 .sh 都有这一行
export LD_LIBRARY_PATH="/usr/lib:/mnt/vendor/lib:${LD_LIBRARY_PATH:-}"

# 日志：追加 + 轮转（不要用 exec > 截断，会丢历史）
LOG="$APPDIR/boot.log"
[ -f "$LOG" ] && [ "$(stat -c%s "$LOG")" -gt 262144 ] && mv "$LOG" "$LOG.1"

# 环境自检：失败时明确报错，不静默退出
[ -d "$APPDIR" ]         || { echo "缺应用目录 $APPDIR"; exit 1; }
[ -f "$APPDIR/main.py" ] || { echo "缺 main.py"; exit 1; }
PY="$(command -v python3)" || { echo "系统未找到 python3"; exit 1; }

"$PY" "$APPDIR/main.py" >> "$LOG" 2>&1
exit 0
```

**四个必做点**：

| # | 做什么 | 不做的后果 |
|---|---|---|
| 1 | 脚本放 `Roms/APPS/PocketTransfer.sh` | 菜单里根本不出现 |
| 2 | `basedir` 自算 + export `BASE_PATH` | 不知道管哪张卡 |
| 3 | 日志重定向到 `boot.log`（追加 + 轮转） | 崩溃无痕迹，无法调试 |
| 4 | **`export PYSDL2_DLL_PATH="/usr/lib"`** | **找不到 libSDL2，秒退** |

**绝对不能做**：❌ 调 `setmode.py` 切显示模式（曾导致 SIGBUS）
❌ `mkdir -p` 建应用目录 ❌ `exec >` 覆盖日志
❌ kill 进程 ❌ 写 `/tmp/.next` ❌ remount ❌ 建软链 ❌ 写 sysfs

## 十二、安全设计要点

| 风险 | 防护 |
|---|---|
| 路径穿越（`../../etc/passwd`） | 掌机端强制路径规范化 + `BASE_PATH` 边界校验 |
| 系统文件被删 | `/mnt/vendor` 等只读 + 三区分类硬编码 |
| 未授权访问 | 首次连接需掌机确认 |
| 中间人窃听 | v1 用 PSK 做 HMAC 完整性校验；TLS 留 v2 |
| 传输残留 | `.part` 后缀临时文件，成功才改名 |
| 磁盘写满 | 传输前检查可用空间 |
| 写到系统区变砖 | 三区分类：警告区两次确认，禁止区直接拒绝 |

**三区分类见 6.3。**

## 十五、关键提醒（2026-10-05 更新）

1. **不要推翻角色划分**（掌机=服务端）。这是掌机侧确认能成立的唯一架构基础。
2. **不要复用 SSH 做产品功能**。架构级不兼容，且丢失自动发现能力。（但开发调试要用它推文件）
3. **★ 显示层必须走 SDL2 `SDL_WINDOW_FULLSCREEN_DESKTOP`。** 裸写 `/dev/fb0` 会被 disp 图层盖住。
   详见 `RG35XXPro-开发成功经验.md`。
4. **★ 不要 `import sdl2.ext`。** 会加载坏掉的 SDL2_image，污染 SDL 状态 → 段错误。
5. **★ `SDL_CreateRGBSurfaceWithFormatFrom` 的首参必须用变量持有。** 传临时对象 → 悬空指针 → SIGSEGV。
6. **部署结构必须照抄原厂**：脚本放 `Roms/APPS/*.sh`，负载放兄弟目录，图标放 `Roms/APPS/Imgs/`。
   **写成目录 = 菜单里不出现。**
7. **launcher.sh 必须 `export PYSDL2_DLL_PATH="/usr/lib"`** —— 缺了会秒退。
8. **不要切换显示模式**（`FBIOPUT_VSCREENINFO`）。写了返回成功但驱动不换，反而 SIGBUS。
9. **不要 kill dmenu / dmenu_ln / loadapp**。会把掌机搞黑屏（我们踩过）。
10. **安全默认值不可妥协**：默认锁定、超时拒绝、禁止区直接拒绝、路径边界强制校验。
11. **单卡用户看不到 TF2 行**。不做灰色禁用项，避免误以为设备故障。
12. **存档路径被重定向过**（`saves_RA/`、`states_RA/`、`save/`），按 `Roms/` 判断安全区会误报。
13. **摇杆在 EV_ABS 不在 EV_KEY**，负值是补码，需要死区与去重。
14. **设备事实一律以本机实测为准**，不要采信泛化的社区结论（本机是 Ubuntu 22.04，不是 Buildroot）。
15. **退出路径必须测"进入→退出→再进入"**。我们在这翻过车（悬空指针只在第二次出现）。

## 十六、开发期操作纪律（用户硬边界）

用户明确规定：**只允许通过 SSH 往掌机推文件，不能对系统其他内容进行任何改动。**

| 禁止 | 原因 |
|---|---|
| ❌ kill 任何进程（尤其 dmenu / dmenu_ln / loadapp） | 会把掌机搞黑屏 |
| ❌ 写 `/tmp/.next` | 那是 dmenu 的私有协议 |
| ❌ 切换显示模式（`FBIOPUT_VSCREENINFO`） | 会 SIGBUS |
| ❌ remount 文件系统 | 用户自己修卡 |
| ❌ 建软链、写 sysfs | 改动系统状态 |
| ❌ 在掌机上装包 / 编译 | 没必要，风险高 |

**应用一律由用户在掌机上手动点击菜单启动。** 自动化脚本只负责推文件 + 校验。
