# 产物结构与依赖

> 版本：**v1.4**（2026-10-05）
> **相对 v1.2 的重大变更**：
> 1. **掌机端改为 Python 3.10 —— 不再需要编译，不再有 aarch64 可执行文件**
> 2. **不再需要 `lib/`**（复用固件自带 SDL2），**不再需要字体文件**（用原厂 `default.ttf`）
> 3. 日志文件名改为 `boot.log`
> 4. `tools/toolchain/`（Zig）降级为**备用**，正常流程不用

---

## 一、掌机部署结构（已实机验证）

```
Roms/
├── APPS/
│   ├── PocketTransfer.sh          # ← 启动脚本，必须在 APPS 根目录
│   ├── PocketTransfer/            # ← 负载目录（脚本的兄弟目录）
│   │   ├── main.py                #   入口
│   │   ├── sdl_display.py         #   SDL2 显示后端（主路径）
│   │   ├── fb.py                  #   裸 fb 后端（兜底）
│   │   ├── boot.py                #   崩溃诊断层
│   │   ├── assets/
│   │   │   └── icon.png           #   菜单图标（另需拷一份到 APPS/Imgs/）
│   │   └── boot.log               #   运行时日志（脚本自动追加 + 轮转）
│   └── Imgs/
│       └── PocketTransfer.png     #   菜单图标（APPS/Imgs/，不是 Roms/Imgs/）
```

> ⚠️ **目录结构不能改**：原厂 launcher **只扫描 `Roms/APPS/` 下的 `*.sh`，目录不列为应用**。
> 依据：rommapp/grout `scripts/Anbernic/Grout.sh` 注释原文
> "the payload lives in the sibling folder (**directories are not listed as apps**)"。
> **已实机验证这个结构正确。**

### 与 v1.2 结构的差异

| 项 | v1.2（C 路线） | v1.4（Python 路线） |
|---|---|---|
| 主程序 | `PocketTransfer`（aarch64 静态二进制，< 500KB） | `main.py` + 若干 `.py` |
| `lib/` 目录 | 需要（自带 SDL2） | ❌ **不需要**（复用固件自带 `/usr/lib/libSDL2-2.0.so.0.12.0`） |
| 字体文件 | `font_cjk.ttf`（子集化，200-400KB） | ❌ **不需要**（用 `/mnt/vendor/bin/default.ttf`） |
| 日志 | `logs/stdout.log` | `boot.log` |
| 编译 | 必须交叉编译 | ❌ **不需要**，`.py` 直接推上去跑 |

## 五、部署流程（照做）

```bash
# 1. 本地静态自检（116 项）
python tools/selftest.py

# 2. 看要传什么
python tools/deploy-only.py --dry

# 3. 部署（只推文件 + 装启动脚本，不启动任何东西）
python tools/deploy-only.py

# 4. 校验 MD5（本地 vs 掌机必须逐字节一致）
#    注意：SFTP 子系统 chroot 到 /mnt/mmc，用 shell 侧 md5sum 更可靠

# 5. 用户在掌机上手动点菜单启动：菜单 → APPS → PocketTransfer

# 6. 出问题读 /mnt/mmc/Roms/APPS/PocketTransfer/boot.log
```

**开发期操作纪律**（用户硬边界）：

> **只允许通过 SSH 往掌机推文件，不能对系统其他内容做任何改动。**
>
> ❌ 不 kill 进程（尤其 dmenu）· ❌ 不写 `/tmp/.next` · ❌ 不切显示模式
> ❌ 不 remount · ❌ 不建软链 · ❌ 不写 sysfs · ❌ 不在掌机上装包/编译

## 六、分发形态

最终交付给用户的是 `PocketTransfer_Roms.zip`，解压后拷入 TF 卡的 `Roms/APPS/` 即可，
**无需任何编译环境、无需安装任何依赖**。

> **双卡用户说明**：RG35XX Pro 有两个卡槽。要同时管理两张卡，需把 `Roms/APPS/` 下的
> `PocketTransfer.sh` + `PocketTransfer/` + `Imgs/PocketTransfer.png` **分别拷到两张卡**。
> 启动脚本会自己算出所在卡的根目录（TF1 → `/mnt/mmc`，TF2 → `/mnt/sdcard`），各管各的。
> 这一条必须写进面向用户的一页纸说明里。

## 附录：launcher.sh 完整内容（v1.4，已实机验证）

```bash
#!/bin/bash
# PocketTransfer launcher for the Anbernic stock OS.
# The stock launcher lists every *.sh in Roms/APPS and runs it with $0 set to its path,
# so the payload lives in the sibling "PocketTransfer" folder.

set -u
progdir="$(cd "$(dirname "$0")" && pwd)"
basedir="$(cd "$progdir/../.." && pwd)"    # Roms/APPS -> 卡根
APPDIR="$progdir/PocketTransfer"

export BASE_PATH="$basedir"                 # 卡根（程序据此认定管哪张卡）
export PYSDL2_DLL_PATH="/usr/lib"           # ★ 必须！原厂 5 个 .sh 都有这一行
export LD_LIBRARY_PATH="/usr/lib:/mnt/vendor/lib:${LD_LIBRARY_PATH:-}"

# 日志：追加 + 轮转（不要用 exec > 截断，会丢历史）
LOG="$APPDIR/boot.log"
[ -f "$LOG" ] && [ "$(stat -c%s "$LOG")" -gt 262144 ] && mv "$LOG" "$LOG.1"

# 环境自检：失败时明确报错，不静默退出
[ -d "$APPDIR" ]         || { echo "缺应用目录 $APPDIR"; exit 1; }
[ -f "$APPDIR/main.py" ] || { echo "缺 main.py"; exit 1; }
PY="$(command -v python3)" || { echo "系统未找到 python3"; exit 1; }

"$PY" "$APPDIR/main.py" >> "$LOG" 2>&1
exit 0
```

### 四个必做点

| # | 做什么 | 不做的后果 |
|---|---|---|
| 1 | 脚本放 `Roms/APPS/PocketTransfer.sh` | **菜单里根本不出现** |
| 2 | `basedir` 自算 + `export BASE_PATH` | 程序不知道管哪张卡，双卡显示错 |
| 3 | 日志重定向到 `boot.log`（追加 + 轮转） | 崩溃 / 缺库无任何痕迹，无法调试 |
| 4 | **`export PYSDL2_DLL_PATH="/usr/lib"`** | **找不到 libSDL2，程序秒退** |

### 绝对不能做的事

❌ 调 `setmode.py` 切显示模式（**曾导致 SIGBUS 闪退**）
❌ `mkdir -p` 建应用目录（掩盖发布包不完整）
❌ `exec >` 覆盖日志（丢历史）
❌ `chmod +x` / `./PocketTransfer`（Python 路线下没这个东西）
