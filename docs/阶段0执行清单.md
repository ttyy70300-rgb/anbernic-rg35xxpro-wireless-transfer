### 而原计划要抓的这几项，实测证明是**误导性**的

| 原计划要抓的 | 为什么误导 |
|---|---|
| `libSDL2.so` 版本（决定链接方式） | ❌ 不需要链接 —— Python 路线无编译 |
| 固件 glibc 版本 | ❌ 不需要 —— Python 脚本不存在 libc 兼容问题 |
| SDL2 视频驱动 `kmsdrm`/`fbdev` | ❌ **这两个都不存在** —— 只有 `mali`/`dummy` |

## 🩹 阶段 0 踩过的三个坑（全部已修）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 点进去闪退 | `launcher.sh` 调 `setmode.py` 切显示模式 → 写越界 **SIGBUS** | 删除 `setmode.py` 调用 |
| 2 | 画面显示"加载中" | 裸写 fb0 被 dmenu 残留图层**完全盖住** | 改用 SDL2 `FULLSCREEN_DESKTOP` |
| 3 | 退出再进闪退（rc=139） | `SDL_CreateRGBSurfaceWithFormatFrom` 收到**临时 bytes** → 悬空指针；外加 `import sdl2.ext` 污染 SDL 状态 | 用局部变量 `buf` 持有；只 `import sdl2` |

**外加两个诊断层缺陷**：

| # | 现象 | 根因 |
|---|---|---|
| 4 | 错误屏全黑 | `fb_var_screeninfo` 偏移错位，bpp 读成 94mm |
| 5 | 兜底屏画不出 | `boot.py` 里两个 `die()` 定义，旧版覆盖新版 |

## 🎓 阶段 0 最大教训

> ### 「先搞清楚屏幕是"单画布"还是"多图层合成器"」
>
> 这个问题没答对之前，所有代码写得再好都是白费。
>
> 我们在裸 framebuffer 上花了大量时间优化性能（29.9 FPS、写回自检 0 异常），
> 但用户屏幕上一直是"加载中" —— 因为画的画在被别人盖住的底层。

**辅助教训**：

1. **GUI 程序必须在真实启动路径上测**（从菜单点进去），SSH 里测 GUI 结论不可信
2. **`ldd` 对静态程序无效，要看 `strings`**
3. **设备事实一律以本机实测为准**（本机是 Ubuntu 22.04，不是 Buildroot）
4. **退出路径必须测"进入→退出→再进入"**（悬空指针只在第二次出现）
